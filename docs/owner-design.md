# №5 — проект глазами заказчика

Заказчик открывает тот же адрес проекта, но видит управление и приватные предложения. По умолчанию открыта вкладка «Предложения». Общие обложка и разделы брифа вынесены в `ProjectHero` и `BriefContent`: публичная страница, форма автора и режим владельца используют один проект.

## Выбор автора

Горизонтальная карточка соединяет автора, навыки, подход, приложенный пример, цену и срок. Детали открываются справа; до 950 px используется полноэкранный native dialog. Поиск охватывает имя, навыки, специализацию и сообщение. Сортировка доступна по дате, цене и сроку; фильтр версии отделяет старые условия от актуальных. Избранные сохраняются в браузере отдельно для заказчика и проекта. Можно сравнить до трёх откликов в одной панели.

«Выбрать автора» открывает подтверждение названия проекта, автора, цены, срока и версии брифа. Подтверждение хранит показанную версию. Если бриф изменился, API отклоняет выбор, UI обновляет проект и блокирует прежнее подтверждение. Предложение к старому брифу остаётся в истории, но недоступно для выбора.

После подтверждения row lock и идемпотентность защищают выбор от дублей и конкурирующих команд. Создаётся соглашение с копией условий, приём завершается. Остальные отклики сохраняются. Страница переходит во вкладку «Работа»: выбранный автор, согласованные условия и переход в существующий workspace. Выбор не запускает оплату. `awarded` обозначен как «Автор выбран»; фактическое состояние соглашения показано отдельно.

## Управление и приватность

Приостановка приёма — отдельный флаг, не новая версия брифа. Команда проверяет владельца, `lock_version` и идемпотентный ключ. Новые отклики и загрузки блокируются; полученные предложения можно просмотреть и выбрать. Возобновление доступно до выбора автора. Изменение брифа продолжает создавать неизменяемую версию.

`owner_context` выдаётся только владельцу: выбранное предложение, доступное ему соглашение и последние 50 событий. Даты и события берутся из сохранённой истории, откликов и audit entries. Public API модулей Talent и Engagements предоставляет профили и сведения о соглашении; marketplace не читает их private models. Профили авторов откликов загружаются по account IDs, независимо от лимита публичного каталога.

Примеры — настоящие файлы откликов. Изображения загружаются через приватный endpoint, только после чистого сканирования; blob URL отзывается при закрытии. PDF скачивается, без выдуманного превью. Автор видит свои предложения, заказчик — все. Гость не получает предложения или события; закрытый проект недоступен посторонним согласно существующей policy.

## Демонстрация

`rails db:seed` добавляет отдельный проект «Айдентика для кофейного бренда NORA» и четыре отклика. Публичный бриф для проверки №4 сохраняется. Демо-вложения используют редакционные изображения MESH, отмечены в сообщениях как демонстрационные и проходят обычную quarantine/ClamAV pipeline. Рейтинги, выполненные проекты и проценты сроков не подставляются. Демо-портреты обозначены как иллюстрации.

Войдите как `client@mesh.local`, пароль `MeshDemo2026!`. [Демонстрационный проект](http://localhost:3100/projects/aed62a01-5ee3-4981-8550-b8f234af31b7). Повторный seed не перезаписывает бриф и не добавляет отклики к новой версии или закрытому проекту.

Применение: `docker compose exec api bin/rails db:migrate`, затем `docker compose exec api bin/rails db:seed`. Сканирование файлов требует `MESH_SCAN_FILES=true` и работающего профиля `files`. Выбранный проект использует существующее рабочее пространство; редизайн №6 не входит в это изменение.

## Проверки

Новые backend-сценарии проверяют паузу и возобновление, повтор команды, конфликт версии, отказ в загрузке и отклике, выбор при паузе, приватность, профиль за пределами каталога и неизменяемые условия соглашения. Browser-сценарии проверяют поиск, сортировку, избранные после reload, сравнение до трёх, drawer на пяти ширинах, старый бриф в открытом подтверждении, отмену и выбор автора.

[Скриншоты и отчёты](screenshots/owner-redesign/README.md) относятся к этому изменению. Финальный manifest связывает результаты с хешами файлов и отдельным production image. Автоматическая проверка Axe не заменяет ручной аудит доступности; работа production frontend проверена отдельно от dev-сервера. Private API для production-проверки проксируется к существующему Rails стенду; полноценный same-origin путь проверяется браузерными E2E на 3100.
