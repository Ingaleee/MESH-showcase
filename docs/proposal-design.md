# №4 — проект глазами автора

Это состояние того же проекта: `/projects/:id?proposal=new`. Кнопка «Предложить цену и срок» открывает рабочую панель; гостю сначала предлагается вход. Заказчик своего проекта видит управление брифом. Название, описание, требования, визуальное направление, материалы и история остаются на странице.

На desktop бриф занимает левую колонку, предложение — правую, начиная с верхней части проекта. На mobile сначала идёт контекст проекта, затем форма и подробный бриф. Ссылки позволяют перейти к нужному разделу. Длинная форма прокручивается вместе со страницей: отправка доступна при любой высоте окна.

В форме — цена в валюте проекта, срок от 1 до 365 дней, сообщение до 5000 символов, необязательный PDF/JPEG/PNG до 10 МБ. Итог обновляется при вводе. Если цена выше бюджета, автор видит подсказку пояснить состав работ. Срок считается после согласования, без выдуманной даты старта.

Черновик автоматически сохраняется через 800 мс и вручную, отдельно для каждого аккаунта и проекта в этом браузере. Сохраняются текст, цена, срок, версия брифа и ID примера; содержимое файла и токены не попадают в localStorage. Выход к брифу сохраняет черновик. После успешной отправки он удаляется. Подтверждение изучения брифа не восстанавливается автоматически.

Если заказчик изменил условия, сервер отклоняет старую версию. Данные формы остаются, обновлённый бриф показывается рядом; автор подтверждает изучение и повторно проверяет цену и срок. Проверка версии, дубликатов и привязка примера выполняются под блокировками в одной транзакции. Повтор запроса с прежним ключом не создаёт второе предложение или вложение.

Вложения хранятся отдельно от личного портфолио. До отправки пример доступен только его автору. После отправки метаданные и прошедший проверку файл доступны автору и заказчику этого проекта. Чужой файл, файл другого проекта и отклонённый сканером файл привязать нельзя. Переданный пример удалить из предложения нельзя. Скачивание — через авторизованный API с attachment disposition, nosniff и private/no-store; публичных Active Storage URL нет. Неиспользованный пример можно удалить из формы; до десяти таких примеров на автора в одном проекте.

ClamAV и очередь `files` проверяют содержимое. До проверки скачивание закрыто. Недоступность сканера приводит к повторной попытке и сохранению карантина. UI показывает фактическое состояние. Для запуска включите `MESH_SCAN_FILES=true` в `.env` и выполните `docker compose --profile files up -d scanner api worker dispatcher`. Первый запуск требует загрузки сигнатур. В остальных средах файловый сервис включается явно.

Карточка профиля получает именно профиль текущего аккаунта через `/creators/mine`, независимо от лимита публичного каталога. Рейтинг, число завершённых проектов и онлайн-статус не придуманы. Обложка и редакционные иллюстрации переиспользованы со страницы №3 и подписаны как иллюстрации MESH, а не документы заказчика.

Скриншоты и подтверждения проверок: `docs/screenshots/proposal-redesign`. Backend-тесты выполняются в отдельной `mesh_test`; существующие проекты и финансовая история локального стенда не сбрасываются.
