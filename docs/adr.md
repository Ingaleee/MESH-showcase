# Architecture Decision Records

Дата: 8 октября 2026. Ниже принятые решения для текущего демонстрационного сценария.

| ADR | Решение | Основание и цена | Когда пересмотреть |
|---|---|---|---|
| 001 | Rails modular monolith + отдельный Next.js | Одна атомарная транзакция для выбора автора; React UX. Цена — два runtime и единый proxy | Независимые команды/нагрузка/изоляция домена дают измеримый выигрыш |
| 002 | Packwerk + явные module APIs | Границы проверяются автоматически; runtime Ruby остаётся гибким | Reflection или общие таблицы начинают обходить правила |
| 003 | Read Committed + locks + SQL constraints | Предсказуемые точки сериализации без глобальных SSI aborts | Появляются инварианты диапазонов, write skew или высокий lock contention |
| 004 | Версии брифа и immutable terms/submissions | Приёмка и расчёты относятся к конкретной договорённости | Нужны команды авторов, этапы или лицензии; тогда меняется модель соглашения |
| 005 | Durable idempotency в primary DB | Повтор команды, результат и эффект атомарны | Появляется срок хранения; сначала определить retry horizon и восстановление |
| 006 | Outbox + separate Solid Queue DB | Разрыв между business commit и enqueue переживает restart | Измерена очередь, для которой PostgreSQL становится bottleneck |
| 007 | Несколько small worker pools | Payment recovery не ждёт обработки больших файлов | SLO и профили CPU/IO требуют отдельного deployment очередей |
| 008 | Финансовый simulator с отдельной DB | Потерянный ответ и восстановление воспроизводятся без реальных денег | Выбран реальный PSP и известны его idempotency, lookup, webhook, refund semantics |
| 009 | Double-entry ledger + deferred triggers | Баланс проверяется после полной сборки журнала; posted history immutable | Новые валюты, reversals, liability accounts, сверка банковских settlement files |
| 010 | Stable provider key + reconciliation | Timeout не означает отказ; backup может отставать от провайдера | Новый provider contract или внешний key retention window |
| 011 | Session cookie + CSRF + один origin | Нет долгоживущего bearer token в localStorage | Нужны native clients или внешние API; проектировать отдельные credentials/scopes |
| 012 | Realtime — подсказка, HTTP — источник | Потеря websocket не теряет данные | Потребуются синхронное редактирование, delivery receipts или message ordering |
| 013 | Quarantine, ClamAV, owner-only download | Непроверенный файл не становится публичным | Нужны опубликованные портфолио, S3/CDN и срок хранения |
| 014 | Money RBS + generated OpenAPI types | Типизация приложена к границам и критичной арифметике | Увеличилась область финансовых правил: расширять Steep target и контрактные тесты |
| 015 | CSP nonce и динамический HTML | Строгая script policy ценой static HTML cache | Измерены SSR cost/traffic и рассмотрена совместимая стратегия SRI |
| 016 | Версия результата включает manifest файлов и готовность к приёмке | Название, текст, состав вложений и их SHA-256 сохраняются атомарно. Отзывы относятся к конкретной передаче; приёмка и замечания сериализуются на соглашении. Цена — явная модель истории и миграция формата digest | Нужны отдельные этапы, частичная приёмка или юридическое подписание; расширять модель контрактов |
| 017 | Приватные проверяемые вложения и ZIP до 50 МБ | Черновики доступны автору; заказчик получает только переданные материалы после ClamAV. ZIP ограничен в памяти. Цена — ожидание проверки и дополнительные запросы превью | Измерены большие результаты или параллельные экспорты; использовать фоновый экспорт и object storage с ограниченными ссылками |
| 018 | Claim tokens для outbox и проверок файлов | Старые jobs и поздние ошибки меняют только собственную попытку. Scanner вызывается вне DB lock; queued token заменяется execution token. Цена — дополнительные поля и порядок обновления consumers перед dispatcher | Нужна длительная работа с heartbeat или lease contention; измерить задержки, затем расширять протокол |
| 019 | Общий auth rate limit в primary PostgreSQL | Лимит переживает restart API и общий для инстансов; HMAC вместо хранения исходного IP. Цена — короткая транзакция и row contention на один IP | Распределённая атака или измеренный auth bottleneck требуют edge protection/отдельного budget store |
| 020 | Readiness primary DB отдельно от liveness | API не объявляет готовность при потере своей базы; отказ queue/scanner виден через метрики и не закрывает чтение. Цена — DB probe и таймауты соединения | Deployment требует агрегированной готовности worker/storage или иной политики деградации |
| 021 | Два GIN pg_trgm индекса вместо отдельного search engine | Замер на 100 000 проектах выявил дорогой substring search. Индексы сохраняют `title OR description ILIKE`, дают проверяемый выигрыш и стоят около 14 МБ на синтетической выборке плюс обслуживание при записи. Миграция строит их concurrently и проверяет `indisvalid` | Релевантность, морфология, запросы без извлекаемых триграмм или нагрузка каталога нарушают измеренный read budget; отдельно измерить write overhead |
| 022 | Quiescent backup DB + inventory приватных файлов | Dump и реальные байты сохраняются при остановленных собственных writers; manifest публикуется последним. Восстановление проверяет строки, SHA-256, версии, triggers и приватное скачивание. Цена — пауза записи и второй storage volume | Требуются online backup/RPO меньше интервала backup; проектировать WAL/PITR и согласованную политику versioned object storage |
| 023 | После restore очередь восстанавливается пустой из durable intents | Восстановленная DB сохраняет outbox и leases; настоящий dispatcher повторяет потерянную доставку после lease, notification effect остаётся один. Цена — задержка восстановления и возможные повторы jobs | Появился важный job без durable source в primary или внешний эффект без идемпотентности; явно добавить recovery protocol до использования такого job |

Микросервисы, Kafka, Kubernetes, GraphQL, Elasticsearch, полный event sourcing и AI ranking не добавлены. Для их появления нужен конкретный изменившийся инвариант, профиль нагрузки или продуктовый эксперимент. Каждое дальнейшее ADR должно содержать измеримый trigger, альтернативы, обратимость, миграцию данных и способ проверки.
