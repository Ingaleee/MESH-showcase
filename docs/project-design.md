# Публичный бриф проекта

Маршрут `/projects/:id` связывает discovery на главной с предложением автора и выбором заказчиком. Демо «Айдентика для кофейного бренда» создаётся через обычный `Marketplace::CreateProject` с ключом `demo-coffee-brief-v1`. Повторный запуск seeds не изменяет существующие версии.

## Интерфейс

Общий header MESH, большой заголовок, редакционный коллаж, категория и статус. В основной колонке — задача, список работ, ожидаемый результат, требования, иллюстрации, материалы и история. Ссылки в меню ведут к настоящим секциям. Иллюстрации открываются в диалоге с переключением и Escape.

Справа — бюджет в реальной валюте проекта, календарный дедлайн и версия условий. Гость открывает вход кнопкой «Предложить цену и срок», автор получает форму стоимости, длительности и подхода, заказчик — редактирование брифа и выбор из приватных предложений. Цена автора может отличаться от бюджета. Длительность предложения и календарный дедлайн показаны как разные условия.

Карточка закрепляется при чтении на desktop. Когда форма выше доступного viewport, закрепление отключается: кнопка отправки остаётся доступной при обычной прокрутке. Ссылка «О заказчике» учитывает высоту закреплённой карточки. На мобильном условия располагаются сразу после обложки. Анимация учитывает `prefers-reduced-motion`.

Сохранение проекта использует общий с главной ключ `mesh:saved-projects:v1`, хранится в браузере и показывает ошибку при недоступном хранилище. Копирование ссылки подтверждается только после успешного обращения к clipboard. Навыки ведут в поиск авторов. Похожие проекты открывают настоящие записи из того же направления; результаты запросов из разных сессий не смешиваются.

## Данные и версии

Миграция `20261007120000` добавляет `expected_result`, `deliverables`, `requirements`, `skills`, `reference_urls`. Поля необязательны при создании API-запросом, но всегда присутствуют в ответе Project. Пустые разделы показываются честно или скрываются. Заказчик может заполнять их в форме создания и редактирования.

Все разделы включены в `brief_snapshot` и фиксируются в соглашении при выборе автора. Предыдущие immutable snapshots не переписываются. Новые поля в схеме Terms остаются optional, чтобы старые соглашения соответствовали контракту.

`ProjectDetail` содержит настоящий `proposal_count` по всем версиям проекта, приватный список доступных предложений и `brief_history`: номер, дата и изменённые поля последних 50 версий. Старые тексты, цены чужих предложений и личные email публично не раскрываются. В начале ограниченного окна история сравнивается с предыдущей версией. Пустые новые поля в старых snapshot нормализуются перед сравнением.

Версия отправляемого отклика фиксируется при открытии формы. При `STALE_BRIEF` страница перечитывает актуальный бриф, сохраняет цену, срок и сообщение и требует подтверждения новой версии. Форма использует обычный submit с предотвращением автоматического сброса React после ошибки. Финальное решение об актуальности версии принимает сервер под блокировкой проекта.

## Материалы и границы

Публичные материалы — ссылки заказчика, до 10 HTTP/HTTPS URL без встроенных учётных данных. Сервер не загружает эти URL. Они открываются с `noopener noreferrer`. Нативные вложения публичного проекта в этой итерации не добавлялись: существующий приватный конвейер портфолио не выдаётся за публичное хранилище брифа. У демо-проекта нет фиктивных PDF/ZIP или кнопок несуществующего скачивания.

Три иллюстрации сгенерированы встроенным image_gen, сохранены в `apps/web/public/images/projects`. Промпты: [project-image-prompts.json](project-image-prompts.json). Это демонстрация вымышленного бренда NORA и иллюстрации MESH, а не загруженные заказчиком референсы. Выдуманные рейтинги, просмотры, онлайн-статусы и география не добавлены.

## Проверка

45 Rails-примеров, включая версии разделов, immutable условия соглашения, приватность, URL-валидацию, ограниченное окно истории и защиту cookie сессии при обычных чтениях. 7 Playwright-сценариев, включая сохранение черновика при настоящем изменении брифа другим аккаунтом, намеренно задержанный гостевой ответ после входа и проверку ProjectDetail по OpenAPI. Отдельно — визуальная проверка пяти ширин, gallery, bookmarks, формы заказчика и автора; Axe WCAG 2.1 AA для desktop и mobile. TypeScript, Prettier, OpenAPI generation, module boundaries, RuboCop и Brakeman.

Обычные GET/HEAD API не обновляют cookie сессии: поздний гостевой ответ не может затереть cookie, созданную входом. `/session` сохраняет bootstrap CSRF, а команды входа и выхода по-прежнему выдают новые cookie. Начальный запрос сессии на frontend выполняется один раз, включая повтор эффектов в development Strict Mode. Срок действия cookie остаётся 12 часов; обычное чтение больше не продлевает его.

Скриншоты и результаты текущей итерации: `docs/screenshots/project-redesign`. Старые скриншоты предыдущих экранов не заменяются.
