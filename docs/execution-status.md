Первый full browser run после пересоздания API не дождался home cards. После явной readiness проверки полный run прошёл 13/13; startup timing — наблюдаемая связь, не доказанная первопричина всех возможных UI отказов. Отрицательный отчёт не переписан в pass.

Release выявил CRLF shell portability issue; исходники shell приведены к LF, правило закреплено .gitattributes. Scanner probe учитывает competing dispatcher claim: сразу после perform_now файл может ещё сканироваться обычным worker; проверка ждёт bounded terminal state.

Повторная подготовка на тесном host дала development HTTP 500 / Errno::ENOMEM в file watcher. [Отрицательный browser report](evidence/publishing-demo-memory-failure/playwright.json) и stages сохранены; interview mode отключает auto-reload и заранее загружает Ruby. Настоящие machine callbacks также выявили CSRF 422; теперь endpoint stateless с обязательной HMAC, а demo ждёт три actual HTTP 200 callbacks и проверяет локальную активную версию после поздней доставки.

## Что остаётся

1. Пользователь создаёт/выбирает GitHub repo; затем настоящие verify → build → scan → GHCR digest → deployment runs и их artifacts.
2. Отдельная Ubuntu VM: Ansible apply дважды, changed=0, runner Online и trusted manual deploy. Docker runner имеет административные возможности на VM; fork PR туда не отправляются.
3. Последующий Kubernetes rollout новых Alpine digests и выбранная durable DB/storage/registry схема. Уже выполненный local cluster не является production HA.
4. Измеренные production user SLIs/error budget, durable telemetry retention, backup encryption/retention/offsite/PITR и recovery на другом host.
5. Две собственные коммерческие истории кандидата и самостоятельная демонстрация кода.
